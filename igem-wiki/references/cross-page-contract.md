# Cross-page contract

Use this contract to stop different wiki pages from telling incompatible versions of the project.

## Canonical facts

Keep one agreed statement for each of the following and reuse it consistently:

- project name and one-sentence purpose;
- primary problem, intended users, and use setting;
- proposed biological mechanism and system boundary;
- success criteria and current maturity level;
- headline quantitative results and their conditions;
- largest unresolved limitation;
- intended implementation path and principal safety assumptions.

## Ownership and links

| Claim type | Canonical owner | Supporting pages |
|---|---|---|
| Problem, users, solution | Description | Home, HP, Implementation |
| Design iteration | Engineering | Experiments, Results, Model |
| Experimental finding | Results or Measurement | Engineering, Description |
| Computational finding | Model | Results, Engineering |
| Stakeholder-caused change | Human Practices | Design, Safety, Implementation |
| Use scenario and readiness | Implementation | Safety, Entrepreneurship, HP |
| Reusable artifact | Contribution, Parts, Hardware, or Software | Results, Awards |

Other pages should summarize and link to the canonical owner. Avoid copying a detailed result into several pages unless a single source fragment is reused programmatically.

## Consistency audit

For each headline claim, check:

1. Same value, unit, sample definition, and condition everywhere.
2. Same evidence status: measured, computed, literature-derived, proposed, or future work.
3. Same maturity language: concept, prototype, proof of principle, validated subsystem, or deployable system.
4. Same user and operating environment.
5. Compatible containment, regulation, cost, scale, and sustainability assumptions.
6. Links lead to the page where the evidence can actually be inspected.
